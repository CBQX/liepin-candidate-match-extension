# 蓝紫视觉与结果层级设计

**日期：** 2026-08-19

**状态：** 用户已批准方案 A

**适用范围：** 猎头匹配助手侧边栏

## 1. 决策摘要

侧边栏采用白色内容卡片与蓝紫渐变品牌系统，强化岗位上下文和分析结论的阅读层级。当前岗位不再使用只能显示单行文本的原生 `select`，改为可访问的自定义双行选择器；分析结果把猎头结论移至结果顶部，并让 AI 额外返回最多三条结构化重点，由 UI 使用粗体显示。

岗位画像、候选人脱敏、DeepSeek V4 Flash、8192-token 上限、一次格式修复重试和三档联系建议等既有业务策略保持不变。

## 2. 当前岗位选择器

- 收起状态第一行显示 `recruitmentProfile.roleTitle`，第二行显示 `company`。
- 未生成岗位画像的兼容岗位使用“待确认岗位”作为第一行，不从原始 JD 猜测岗位名。
- 展开列表中每个选项保持相同双行结构，并标记当前岗位。
- 触发器使用 `aria-haspopup="listbox"`、`aria-expanded` 与 `aria-controls`；选项使用 `role="option"` 与 `aria-selected`。
- 支持点击、Enter/Space 打开，ArrowUp/ArrowDown 移动，Enter/Space 选择，Escape 关闭；失焦关闭。
- 岗位切换失败时继续显示原岗位，既有中文错误提示保持不变。
- “添加新岗位”按钮位置与行为不变。

## 3. 分析结果层级

结果页从上到下依次展示：

1. 报告标题；
2. 猎头结论，包括一段综合建议和 1–3 条粗体重点；
3. 综合匹配分与联系建议；
4. 主要匹配理由；
5. 主要顾虑或信息缺口；
6. 建议核实问题。

轻量结果协议新增：

```ts
conclusionHighlights: string[]; // 1–3 条，每条 1–120 字符
```

重点由 AI 从综合建议中提炼。UI 只渲染文本节点与 `<strong>`，不解析 Markdown 或 HTML。候选人隐私字段不得进入重点；字段仍通过同一个 Zod 结果协议和一次修复重试校验。

## 4. 蓝紫视觉系统

- 页面背景：接近白色的冷色底，加左上蓝色、右上紫色的低透明度光晕。
- 主渐变：`#4f46e5` 到 `#7c3aed`；用于主按钮、分数、选中状态和少量品牌强调。
- 正文：深蓝黑；次级信息：灰蓝；内容卡片：白色。
- 卡片使用淡紫边框、克制阴影和一致圆角；不使用大面积高饱和背景。
- 输入框、复选框、按钮、加载动画、结果证据卡、岗位画像卡统一使用主题变量。
- 错误继续使用红色，警告继续使用琥珀色，不用蓝紫色掩盖语义状态。
- 所有键盘焦点提供清晰可见的蓝紫焦点环；禁用状态保持可辨认。

## 5. 兼容与验证

- 不新增图片、字体、UI 库或 Markdown 依赖。
- 支持 Chrome 116+ 的 Windows/macOS 侧边栏。
- 旧的内存分析结果不做迁移；重新分析即可得到新增重点字段。
- 自动化测试覆盖双行岗位文本、选择器交互、岗位切换失败回退、结论顺序、重点粗体、协议边界、提示词字段与完整工作流。
- 完整验证包括类型检查、Vitest、生产构建和 ZIP 根目录检查；真实猎聘页面和 DeepSeek 仍由用户手动验收。

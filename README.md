# 猎头匹配助手

> **阶段 C 可行性验证版**：仅供授权的内部试用与流程验证，不替代猎头判断，也不用于自动淘汰候选人。

这是一个面向 Chrome 116+ 的 Manifest V3 侧边栏插件。猎头配置招聘公司、职位 JD 和个性化要求后，可在自己主动打开的猎聘单个候选人详情页中点击“匹配分析”，校对提取内容，再获得包含分数、证据、风险、信息缺口和推进建议的结构化报告。

同一份构建产物支持 Windows 和 macOS Chrome。当前版本默认使用 DeepSeek，采用用户自带 API Key（BYOK），并通过可替换接口隔离页面提取、岗位仓库、评分领域模型、模型供应商和界面状态。

## 当前范围

- 只处理用户当前打开并主动触发分析的猎聘单个候选人详情页。
- 阶段 C 当前仅审核支持 HTTPS 猎聘域名下的 `/candidate/<候选人标识>` 详情路由：标识必须是 6–20 位非零开头数字，或 12–64 位、同时含字母和数字的受限不透明标识（允许 `_`、`-`、尾斜杠和查询参数）。`search`、`list` 等保留路径以及首页、公司和职位页会直接拒绝。整页文本兜底还要求页面存在已审核的单候选人 DOM 标记；真实猎聘路由和标记仍需在授权环境完成验收后扩展。
- 不批量分析、不自动翻页、不点击隐藏内容、不后台监控。
- 公司、职位 JD 和个性化要求均为必填；支持保存多个岗位并切换一个当前岗位。
- 提取结果必须由用户校对并确认后，才会提交分析。
- 内置 DeepSeek V4 Pro（默认）和 DeepSeek V4 Flash 两个模型选项。
- 候选人草稿、脱敏上下文与分析结果仅存在于当前内存状态，不写入 `chrome.storage`、IndexedDB、日志、遥测或分析系统；取消、切换岗位、页面变化或会话结束时按边界清除。
- 提交模型前会移除直接联系方式、猎聘 URL/ID，并用提取阶段识别到的姓名令牌在所有分区再次完整脱敏；脱敏令牌本身不发送给模型。用户还必须勾选确认已人工检查姓名、联系方式和猎聘 ID 后才能提交。
- 进行中的分析使用请求 ID 和 `AbortSignal`；取消、切换岗位、换页或结束会话会通知 Service Worker 终止对应模型请求，晚到响应不会恢复旧状态。

## 构建与验证

准备环境：

- Node.js **20.19.0 或更高版本**（`package.json` 已声明最低版本；测试栈固定为兼容 Node 20.19.0 的版本）
- npm（使用仓库内的 `package-lock.json`）
- Chrome 116 或更高版本

在项目根目录执行：

```bash
npm ci
npm run verify
```

`npm run verify` 会依次运行 TypeScript 类型检查、全部自动化测试和生产构建。成功后，可加载的未打包扩展位于项目根目录的 `dist/`。

## 在 Chrome 中安装

1. 打开 `chrome://extensions`。
2. 开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本项目构建生成的 `dist/` 目录。
5. 固定“猎头匹配助手”图标，并点击图标打开侧边栏。

代码或配置更新后，重新执行 `npm run build`，再到 `chrome://extensions` 点击扩展卡片上的“重新加载”。正式内部试用前，请按 [MVP 冒烟测试](docs/qa/mvp-smoke-test.md) 在目标电脑上逐项验证。

## 首次设置 DeepSeek

1. 在侧边栏中选择 DeepSeek 模型。
2. 输入自己的 DeepSeek API Key。
3. 保持“记住此设备”未勾选时，Key 默认保存在仅可信扩展上下文可访问的 `chrome.storage.session`，关闭并重启 Chrome 会话后应消失。
4. 只有用户主动勾选“记住此设备”时，供应商设置（包括 API Key）才会写入扩展源 IndexedDB；猎聘 Content Script 运行在网页源，不能打开扩展源数据库。
5. 点击“验证并保存”，验证成功后添加岗位。

安全提示：阶段 C 没有公司后端，模型请求从插件直接发送到 DeepSeek。“记住此设备”使用的扩展源 IndexedDB 仍是**未加密的本地持久化**，不是企业密钥保险箱，也不能替代操作系统钥匙串；共享电脑或不受信任设备请勿启用。只使用为内部试用单独创建、可撤销且额度受控的 Key，不要把 Key 写入仓库、截图或问题报告。

## 使用流程

1. 添加岗位，填写公司、职位 JD 和个性化要求。
2. 在猎聘中主动打开一个候选人详情页。
3. 点击侧边栏中的“匹配分析”。
4. 检查并编辑候选人预览；缺失信息不会自动视为不满足。
5. 阅读数据发送提示，人工检查姓名、联系方式和猎聘 ID，勾选隐私确认后点击“确认并分析”。
6. 核对六维评分、硬性条件证据、匹配/不匹配理由、风险、信息缺口、核实问题、沟通建议和猎头结论。
7. 切换岗位后，重新提取并分析；上一岗位的候选人草稿与结果会被清除。

## 数据边界

持久存储的内容仅限：

- 扩展源 IndexedDB 数据库 `liepin-candidate-match-extension`：岗位列表、当前岗位 ID；以及用户明确选择“记住此设备”时的模型供应商设置。
- `chrome.storage.session`：默认的模型供应商设置与 API Key。
- `chrome.storage.local`：仅用于从早期版本迁移上述三个旧键；启动后迁入 IndexedDB 并删除旧副本，正常运行时不保存这些敏感/内部状态。

不会持久化候选人页面内容、编辑后的候选人草稿、姓名脱敏令牌或分析结果。IndexedDB/会话仓库通过可替换接口注入，阶段 A 可替换为公司后端而不改变工作流。扩展不申请 `tabs`、`history`、`cookies`、`webRequest`、`unlimitedStorage` 或全网站通配访问权限，只申请侧边栏、存储、猎聘页面和 DeepSeek API 所需权限。

内部验证不得使用未经授权的候选人数据。工程冒烟优先使用合成页面或充分匿名化的内部样本；真实猎聘验证必须由用户在其已授权会话中主动执行。

## 演进路径与可替换边界

- **当前阶段 C（可行性验证）**：纯插件、DeepSeek BYOK、本地岗位、无候选人历史。
- **下一阶段 A（内部稳定使用）**：用公司后端代理替换直接模型适配器和本地密钥存储，加入员工身份、企业策略及受控运维能力。
- **未来阶段 B（商业化）**：在相同稳定协议上增加多租户、组织隔离、角色权限、配额计费、审计和多模型策略。

页面提取器、岗位领域模型、混合评分、供应商注册表、仓库接口和侧边栏协议彼此隔离。阶段 A/B 应在这些接口后替换基础设施，避免重写已验证的猎聘提取和猎头工作流。

## 验收状态

自动化验证和 `dist/` 静态检查由开发流程完成。Windows Chrome、授权猎聘会话、真实 DeepSeek 连通性以及 3 个岗位 / 30 份匿名样本的内部试点，必须由用户在目标环境完成并记录在 [MVP 冒烟测试](docs/qa/mvp-smoke-test.md)；未记录前不得把本版本标记为阶段 A 或正式产品。
